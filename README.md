# Синхронизация доступа к разделяемому состоянию

## Контекст

В многопоточной программе есть крупный объект `State`, содержащий, например, большой вектор данных. Этот объект:

- **читается** множеством рабочих потоков;
- **обновляется** одним выделенным потоком;
- при обновлении создаётся **новая копия** состояния, которая после модификации заменяет старую;
- старая версия должна быть уничтожена только после того, как **все читающие потоки завершат работу с ней**.

В приложенном файле `baseline.cpp` приведена эталонная (но неоптимальная) реализация на `std::shared_mutex`. Она работает, но:

- каждый читающий поток захватывает `shared_lock` на время доступа к `std::shared_ptr<State>`;
- писатель захватывает `unique_lock` для замены указателя;
- это создаёт ненужные накладные расходы на синхронизацию при каждом чтении.

## Задача

Предложите и реализуйте **более эффективный механизм синхронизации** для данной задачи, учитывая:

1. **Один писатель, много читателей.**
2. **Писатель обновляет состояние редко** (например, раз в 100 мс в тесте, но в реальности может быть **гораздо** реже).
3. **Читатели обращаются к состоянию очень часто** (тысячи/миллионы раз в секунду).
4. **Копирование `State`** — дорогое (большой вектор), но писатель готов его платить.

## Вопросы

1. Корректно ли убрать захват мьютекса для доступа к указателю из эталонной программы? Если нет то почему?
2. Можно ли убрать захват мьютекса если использовать `std::atomic<std::shared_ptr<State>>`? Чем плоха такая реализация? Возможно ли адаптировать `std::atomic<std::shared_ptr<State>>` под данную задачу?
3. Применимы ли механизмы синхронизации RCU (Read-Copy-Update)/hazard pointers к данной задаче?
